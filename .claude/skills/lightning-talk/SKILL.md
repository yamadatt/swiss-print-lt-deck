# Lightning Talk Deck Builder（Swiss Print）

同梱のテンプレートを使い、単一HTMLのスライドデッキを作成します。
デッキは1920×1080で描画され、矢印キーで操作でき、PDF出力できます。

## デザインの規律

このテンプレートはスイス・インターナショナル様式で組まれています。**流し込みの際にこの規律を崩さないでください。**

1. **角丸 0 / グラデーション 0 / 影 0 / 絵文字 0。** 面を分けるのは罫線と余白だけ。
2. **アクセント（朱赤 `--accent: #D6402B`）は1枚に1〜2箇所まで。** それ以外は `--text` と `--muted` で組む。
3. **ラベルに `//` を使わない。** kicker は `06 / KEY POINTS` の形。
4. **タイプスケールの8段（`--type-*`）から外れない。** 新しいサイズを足したくなったら、たいていは情報を削るほうが正しい。スライドは `overflow:hidden` なので、大きいサイズを直に書くと収まらない行が黙って切れる（枠内で切れるため、はみ出し検査には出てこない）。
5. **罫線は4段の濃度階層を守る。** `--grid`(.05) < `--line`(.14) < `--tick` / `--line-2`(.34)。縦罫と横罫を同じ濃さにすると交点が網目になって読めなくなる。

## `assets/` の内容

- `template.html` — 全22種のレイアウトを1枚ずつ含む参照デッキ。これを出発点としてコピーする。
- `deck-stage.js` — `<deck-stage>` Web Component。キーボード操作、自動スケール、サムネイル一覧、PDF印刷、ページ番号の自動採番を扱う。**HTMLと同じ階層に必須。**
- `image-slot.js` — `<image-slot>` のドラッグ＆ドロップ画像プレースホルダー。**HTMLと同じ階層に必須。** この案では角丸を使わないので `shape="rect"` を指定する。

配色・フォント・文字サイズを変えたい場合は、`template.html` 冒頭の CSS 変数（`--accent` / `--font-display` / `--type-*`）を直接編集する。

## 詳細リファレンス（必要になったときに読む）

- `references/slide-types.md` — 全22種のスライド種別と編集ポイント、スライドの追加・削除
- `references/cover-image.md` — 表紙に写真を敷く手順（この案は `bg-shade` を使わず `.plate` 方式）
- `references/aws-diagram.md` — AWS構成図と公式アイコンへの差し替え
- `references/validation.md` — はみ出し自動チェック、完成チェックリスト、PDF自動出力

## ワークフロー

1. **先にトーク内容を確認する。** HTMLを書く前に、次を確認してください。
   - トークタイトル、登壇者名、ハンドル名、イベント名、日付
   - **持ち時間**（5分LT / 10分 / 15分など）。表紙の時間バッジ（`5 min`）も実際の時間に合わせる
   - 中心メッセージ（聴衆に覚えてほしいこと）
   - 大まかな構成と、強調したい具体的な数字、コード、Before/After、引用

   情報が不足している場合は確認してください。短いアウトラインだけでも十分です。
   不明な統計や成果を勝手に作って、ユーザー本人の実績のように見せないでください。不明な箇所は明確なプレースホルダーにしてください。

2. **スライド一覧を決める。** 枚数は持ち時間から決めます: **5分 → 8〜12枚 / 10分 → 12〜18枚 / 15分 → 15〜25枚**。
   よくある構成: Title → About → Intro → Agenda → Section → 1〜3枚の内容スライド（Stat / Chart / Code / Bullets / Steps / Diagram / AWS / Screenshot / Shot Compare / Table / Do-Don't / Before-After / Photo）→ Quote（任意）→ Summary/CTA → Thanks
   各種別の編集ポイントは `references/slide-types.md` を参照。

3. **自己完結した出力フォルダを作る。** デッキは必ず専用フォルダに入れ、ZIP化してそのまま渡せる状態にします。フォルダ名はトーク名のkebab-case slugにします（例: `my-talk-deck/`）。
   - **置き場所を先に確認する。** 既定は**作業ディレクトリ直下の `<slug>/`**。フォルダを作る前に「ここに作ります」と一度伝え、別の場所を指定されたらそちらに作る。
   - `assets/template.html` を `<slug>.html` としてコピーする。
   - `deck-stage.js`・`image-slot.js`（どちらも必須）を同じ階層にコピーする。
   - 写真を使う場合は `img/` サブフォルダを作り、相対パス（例: `img/foo.png`）で参照する。

   その後、HTML内の `<section>` ブロックを編集します。必要なものだけを残し、不要なものを削除し、サンプル文言を実際の内容に置き換えてください。
   編集はすべて出力フォルダ内で行い、未使用画像・元PDF・一時スクリーンショットなどの作業用ファイルはフォルダの外に置きます。

4. **番号を整える。** `.pageno`（`02 / 22`）は `deck-stage.js` が表示時に自動採番するため**編集不要**です。kickerラベルの番号（`06 / KEY POINTS`）と `s-section` の章番号（`.chapter` / `.idx`）は自動採番されないので、スライドの増減に合わせて手動で振り直してください。

5. **文字の折り返しを整える。** テンプレートは `word-break: keep-all` を基本とし、対応ブラウザ（Chrome/Edge 119+）では `word-break: auto-phrase` により文節単位で自動折り返しされます。ただし:
   - 非対応ブラウザでは keep-all のままなので、長文が折り返されず枠からはみ出して欠けます（`overflow:hidden`）。**重要な行は意味の切れ目（読点「、」・句点「。」の後など）に `<br>` を明示的に入れる**のが確実です。
   - `s-intro` の `.lede`（116px大見出し）は自動折り返しに任せず、`<br>` で行を確定させます（1行9〜12文字程度）。
   - 英単語・製品名（`Lambda` `DynamoDB` など）の途中で改行が割れていないか確認します。

6. **コードスライドの落とし穴に注意する。** `.c-hl`（注目箇所の左赤罫）は `display:block` です。複数行をまとめるときは **1つの `.c-hl` の中に改行ごと入れてください**。`.c-hl` を複数並べて span の間に改行を置くと、その改行が空の行ボックスになり、行数が見た目より増えて `overflow:hidden` で末尾が切れます（枠自体は収まるので通常のはみ出し検査に出ません）。

7. **検証する。** `references/validation.md` の手順で確認します。
   - Playwright MCPが使える場合: はみ出しの機械検出＋全スライドのスクリーンショット確認。**`overflow:hidden` の内側で中身が切れていないか（`scrollHeight > clientHeight`）も必ず併せて検査する。**
   - 使えない場合: `open <slug>-deck/<slug>.html` でブラウザ表示し、全スライドを目視確認（矢印キー/Spaceで移動、`R` で先頭へ、`T` で左のサムネイル一覧を表示/非表示）。
   - 完成チェックリスト（サンプル文言の残り、idの重複、画像パス切れ）も同ファイルにあります。

8. **PDF出力する（依頼された場合）。** headless Chromeでの自動出力、またはブラウザの印刷ダイアログ。手順とコマンドは `references/validation.md` 参照。
